# backboardd の待機進捗と未完了候補

`a04br3-gio=4` は既定OFF。Mesaは変更せず、既存の `=3` に追加する
機種固有診断。短い成功待機のbegin/terminalログは出さず、重要な待機の
枠を消費しない。接続・pid・tid・fenceごとの系列番号は従来と同じ。

完了したtimeoutを同一系列で合算し、250ms、500ms、1秒、2秒、4秒…の
倍増閾値に達した時と、250ms以上の系列が非timeoutで終わった時に出す。
`sum_ns`、`count`、`errors` は系列の先頭からの累積値であり、繰り返し出た
系列を足し合わせない。非timeoutで系列を終了し、異なる接続は混ぜない。
集計枠はグローバルの1秒窓あたり最大2件、超過は `suppressed_series`。
開始ログ枠は使わない。短い成功は集計枠を使わない。

診断スレッドが250msごとに有限スロットを確認し、開始記録から500ms以上
経過した未完了候補を `wait active` として出す。これは測定処理が完了を
まだ記録していないという意味であり、実際にCPUがWaitFence内で動作中、
あるいは必ずハング中である証明にはならない。進捗枠は集計とは別に
グローバルの1秒窓あたり最大2件。順送りで候補を選び、同じ系列は1秒
以上空ける。抑制は `suppressed_active`、ロック競合は `busy`、枠不足は
`full`、期限切れは `evicted`/`expired_pending`、時刻順等の欠測は `late`。
スレッド生成失敗は `monitor unavailable` を出し、進行中の観測は行わない。
10秒周期のカウンタや既存リングがpanic前に出る保証はない。

枠は16、待機中の追跡も65秒後に失効し得る。試行ロックは待たないため、
待機開始・終了の競合で欠測する。有限の率制限・CPU脱スケジュール・UARTの
同期出力・panic中の出力欠落は避けられず、未出力は対象がWaitFenceに入って
いないことの証明ではない。ウィンドウ境界をまたぐと最大数が短時間に
連続し得る。既存 `=3` の挙動は変えない。診断スレッドの250ms起床とIOLogは
タイミングおよび充電ownerに間接的な影響を与え得るため、実機で要比較。

`start_ns`、`end_ns`、`pending_ns`、`now_ns` はkernelの `mach_absolute_time`
由来で、Mesaの `QT`/`XT` は `CLOCK_MONOTONIC` 由来。kernelのイベント時刻
`K_event` と同時刻校正点 `U_ref`,`K_ref` が実測できた場合だけ
`K_event+(U_ref-K_ref)` を用いる。過去の約33秒差は符号・誤差・安定性を
校正していないため固定補正値として使わない。durationはepoch補正不要。
