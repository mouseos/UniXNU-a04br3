# 充電 snapshot の取り直し候補

観測：初回 read 約2.211秒を含め snapshot 約2.244秒、完了時点で
firmware 引継ぎ期限まで約9.07秒。スレッド停止時間と I2C の実転送時間は
分離できていない。初回 snapshot には従来の1秒上限が適用され、petは行われない。

候補は最大3回、完全かつ policy と fault history が正常で、snapshot 自体の
経過時間が1秒を超えた場合にのみ取り直す。各回に既存の1秒上限を適用し、
read失敗、部分読出し、fault、設定不一致、引継ぎ・20秒期限到達で停止する。
初回履歴を保持し、古い snapshot から kick しない。kick の直前に同じ期限を
再確認し、完了時に1秒又は20秒期限を越えていれば継続成功と扱わない。
次回の20秒判定は kick の完了時刻ではなく、その試行の開始時刻を使う。

kick の直前確認とハードウェアへの書込みの間に OS が停止する可能性を
ソフトウェアだけでは排除できない。完了時の期限超過は事後検出であり、
その時点では書込みが既に発生している可能性がある。スレッド優先度変更や
preemption 禁止によって解決したとは主張しない。実機の時間、FAULT、連続pet、
充電電圧・電流は未確認。fastbootからこのコードは動作しない。
